# 🎬 MovieIQ — Predictive Analytics on Film Success

A Streamlit dashboard with a custom indigo/gold theme and sidebar navigation, analysing and predicting whether a movie will succeed, using budget, popularity, runtime, and average votes.

**Live app:** _add your Streamlit Community Cloud link here after deploying_

## Files
- `MovieIQ.py` — the Streamlit app
- `train_model.py` — data prep, EDA, statistical tests, and Random Forest training (run this first to generate `model.pkl` and the charts in `assets/`)
- `movies.csv` — dataset (budget, revenue, popularity, runtime, vote_average, title, genres)
- `requirements.txt` — dependencies
- `assets/` — saved charts (generated by `train_model.py`)
- `model.pkl` — trained model + metrics (generated by `train_model.py`, not committed if large — regenerate with `python train_model.py`)

## Run locally
```bash
pip install -r requirements.txt
python train_model.py      # generates model.pkl and assets/*.png
streamlit run MovieIQ.py
```

## Stage 0 — Problem Statement

**1. What makes a movie "successful"?**
A movie is labeled successful when its box-office **revenue exceeds its production budget**: `success = 1 if revenue > budget else 0`. It's a simple, purely financial definition — it doesn't account for critical reception or long-term (streaming/merchandise) earnings, only whether the theatrical revenue covered the budget.

**2. Why is this valuable, and to whom?**
- **Studios** can use a success prediction to decide how much marketing spend or which release window to commit to before greenlighting a project.
- **Investors/production financiers** can use it as one input (alongside script quality, cast, etc.) when deciding whether to fund a film, since it flags projects whose budget-to-expected-return profile looks risky.

**3. Objective & steps**
Objective: build a model and dashboard that predicts whether a film will be financially successful, and lets a user explore what drives success.
Steps: (1) clean and label the data, (2) explore relationships between budget/popularity/runtime/votes and success, (3) statistically test whether specific features differ by outcome, (4) train and evaluate a Random Forest classifier, (5) ship it as an interactive Streamlit app.

**4. Classification problem**
This is **binary classification** — the target variable is `success` (0 = not successful, 1 = successful), and the model learns to assign one of these two classes to a new, unseen movie based on its input features.

## Stage 1 — Data Preparation
- Dataset: 2,000 rows, 7 columns (`budget, revenue, popularity, runtime, vote_average, title, genres`). No missing values or zero budgets/revenues in this dataset, but `train_model.py` still filters out any `budget <= 0` or `revenue <= 0` rows defensively — a zero would make the success rule meaningless and could break ratio-based features if added later.
- `success` column: 80.7% of movies are labeled successful in this dataset — it's **imbalanced**, which is worth noting when judging accuracy (a model that always predicts "success" would already score ~80%).
- `genres` is a stringified list of dicts (e.g. `"[{'id': 18, 'name': 'Drama'}]"`). It's parsed with `ast.literal_eval` and the first genre's name is extracted into a clean `genre` column for filtering and grouping.

## Stage 2 — EDA
See `assets/budget_vs_revenue.png`, `assets/success_by_genre.png`, `assets/correlation_heatmap.png`, and the "EDA" tab in the app. In this dataset, genre success rates are fairly flat (79–82% across all genres), and budget/popularity/runtime/vote_average show weak correlation with the success label — a sign the data is close to randomly generated rather than reflecting real market patterns.

## Stage 3 — Statistical Testing
- **T-test** (vote_average, success vs not): see the "Statistical Tests" tab for the live t-statistic and p-value.
- **Chi-square** (genre vs success): see the same tab.
- **On p-values:** a p-value tells you the probability of seeing a difference at least this large if there were actually no real difference between the groups (the null hypothesis). We used the standard **0.05** threshold — below that, we call the result statistically significant.

## Stage 4 — Modeling
- Features used: `budget, popularity, runtime, vote_average`. `title` was excluded (not predictive, just an identifier) and `revenue` was excluded because it's literally used to compute the target — including it would leak the answer.
- Split: 80/20 train/test, stratified on `success` so both sets keep the same class balance. A held-out test set is essential to check the model isn't just memorizing the training data.
- **Random Forest**, in plain terms: it builds many decision trees, each trained on a random subset of the data and features, and each tree "votes" success or not; the forest takes the majority vote (or averages probabilities), which makes it more stable than any single tree.
- See the "Model Performance" tab for accuracy/precision/recall, the confusion matrix, and feature importance.

## Stage 5 — Streamlit Dashboard
The app has 5 tabs: Overview (filtered table + download), EDA (charts), Statistical Tests, Model Performance, and Predict (live input → prediction). Sidebar lets you filter by genre and minimum vote average, and all tabs respond to those filters where relevant.

## Reflection
This dataset looks synthetic/randomly generated — genre success rates barely vary and the statistical tests come back non-significant, so **I wouldn't trust MovieIQ's predictions on a real greenlight decision** in its current form; a model trained on real box-office data with more features (cast, marketing spend, release date/season, franchise vs. original) would be far more credible. One concrete improvement: add real historical data (e.g. TMDb full dataset) and engineer a marketing-spend or franchise-flag feature, since those tend to matter more for real-world box office outcomes than runtime or vote average alone.

## Stage 5 — Streamlit Dashboard & Deployment

- Navigation uses a sidebar radio menu (Overview / Explore the Data / Statistical Tests / Model Performance / Predict a Movie) instead of top tabs, alongside a custom indigo/gold theme (`.streamlit/config.toml` + inline CSS) so the app has its own visual identity rather than default Streamlit styling.
- The EDA and stats results from `train_model.py` are shown directly in the app (as saved chart images and printed metrics).
- The Predict page takes budget, popularity, runtime, and vote average as input and returns a Success / Not Successful call with confidence, using the trained Random Forest.

## Reflection
Confidence in MovieIQ's answer for a real studio would be **low-to-moderate**. Two honest limitations:
- **Class imbalance**: ~81% of movies in this dataset are labeled "successful," so the model reaches ~80% accuracy largely by leaning toward predicting "success" — its recall on true failures is weak (visible in the confusion matrix).
- **Missing real-world signal**: the model only sees budget, popularity, runtime, and vote average — it has no information about cast, director, marketing spend, release timing, or franchise/IP value, all of which matter a lot in real box-office outcomes.
With more time, I'd rebalance the classes (e.g. class weighting or resampling) and add richer features (cast/director track record, release month, franchise flag) before trusting this for a real greenlight decision.
